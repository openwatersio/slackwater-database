# Country resolution

Production country lookups use c5y-n8r dataset 6 at immutable commit `f0587eaf0f5a14997f829f89bd1752fcd293a2f8`, from [c5y-n8r #312](https://github.com/openwatersio/c5y-n8r/pull/312). `packages/database/src/country.ts` opens it once, lazily, and performs namespaced point lookups. The build embeds the same binary into Node, browser and Worker bundles so `buildDatabase()` needs no runtime filesystem or network access. The published package includes the binary, release metadata, evidence companion and upstream notices in `dist/generated/`.

`countryByIso` handles alpha-2, alpha-3 and numeric ISO codes. Names use exact upstream spellings under the registry's normalization rules. Unknown, ambiguous, retired, deprecated and outside-date results remain unresolved. A tentative current answer with explicitly uncertain historical bounds is usable; this does not certify the data or its historical dates. The reader retains the dataset version and uncertainty in the underlying binary.

The JavaScript package exports `countryAliases(code)` for clients building search indexes. It accepts the same ISO code forms and returns active registry names for that country other than the registry display label. Names may be shared by multiple countries and are suitable for search, where each country can keep its own match. Unknown and retired codes return an empty array. The aliases do not change station identity, display labels or routes.

Source station records preserve their explicit alpha-2 identity. Geocoding, curated location codes, maritime zones and TICON imports resolve their supplied identifiers without converting codes to display names first. Other importers may supply fixed provider country names, which normalization resolves to an alpha-2 identity. Country-specific datums and source jurisdictions use codes. The Western Samoa name retains its existing WS compatibility mapping. The published builder accepts recognized aliases for the same code, plus seven exact legacy display-name/code pairs from `country-code-lookup` 0.2.1: FK/Falkland Islands (Islas Malvinas), RE/Reunion, MF/Saint Martin, AX/Åland Islands, BQ/Bonaire, VI/Virgin Islands and SH/Saint Helena. Those explicit pairs do not create worldwide aliases for the bare names.

The consumer coverage includes all 8,739 stored source records, the 157 country codes in the GeoNames place snapshot, and curated location codes. The complete catalogue comparison retains all 12,407 stations and published routes, with changes confined to country and continent labels. The standalone [migration diagnostic](country-resolver-spike.md) retains its frozen baseline and source-context evidence.

Wikidata's missing metadata remains visible. Åland has no P30 continent claim in the pinned snapshot, tracked in [c5y-n8r #283](https://github.com/openwatersio/c5y-n8r/issues/283). Its AX identity resolves, while its continent remains empty. A fresh source import requiring that absent continent fails for review; production's current station inventory does not require AX as a station identity. Evidence research is asynchronous and does not block admission of faithful existing Wikidata values.

Country and continent labels use the pinned dataset immediately, including records cached with the former library’s labels. Explicit curated continent overrides retain precedence. The supported ISO set is the pinned Slackwater corpus, not every country in the former library. The `1.0.4-beta` prerelease base requires coordinated consumer opt-in for these metadata and coverage changes. Raw source files retain their existing cached labels until their providers are refreshed; those cached continent labels do not control the resolved catalogue.

Source refreshes stop on unsupported maritime-zone or TICON country identifiers. TICON resolves its complete source-country inventory before a shard writes data; its CSV country field contains ISO codes such as SHN, while the diagnostic’s `originalCountry` refers to a cached display label. The two explicitly researched Taiwan corrections retain precedence. Update the immutable dependency pin from a reviewed merged country-registry revision; the Dependabot group does not establish dataset review or promise automatic discovery of new data.

If rolling back after refreshing cached source or place data, restore the matching data snapshot or reimport it with the older resolver. Reverting only the reader pin can leave newer country vocabulary in those caches.

XTide release assets use the same country labels in station names and country attributes. The migration renames 145 of the 8,963 exported XTide locations; saved selections keyed by those names need reselection. Generation validates name limits and uniqueness before writing the harmonics and offsets inputs. Station IDs and Slackwater routes remain unchanged.
