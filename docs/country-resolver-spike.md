# Country resolver comparison

This diagnostic evaluates `@openwaters/c5y-n8r` against Slackwater’s source-country inputs. The separately installed public GitHub dependency is pinned to commit `e82a2a9e426ce997dbd8e467d00abdabe6e8b2a9`. Production continues using `country-code-lookup`; the diagnostic never substitutes unresolved answers or rewrites station data.

Faithful ingestion of Wikidata labels, aliases and claims is trusted for data admission, with source revisions, statement identities and qualifiers preserved in provenance. Independent certification and complete upstream references are optional quality signals, pursued asynchronously. They do not block admission of faithfully mapped upstream facts. Local aliases, territory interpretations and other project policy decisions still need explicit provenance and compatibility decisions.

## Run

Use the repository’s pinned Node/npm versions and run `npm ci`. Install the diagnostic separately, then run it:

```sh
npm ci
npm ci --prefix spikes/country-resolver
npm run check --prefix spikes/country-resolver
npm run report:country-resolver -w packages/stations
```

The command writes `tmp/country-resolver.json`. An optional argument sets another output path, relative to the command’s working directory (`packages/stations` for the workspace command). Country values must be nonempty strings within the reader’s 1,024-character limit; invalid records stop the diagnostic. The report reads every source JSON record in `data/` and compares its country input with `countryByName`, using the production name-lookup function. Its Western Samoa and Cape Verde aliases apply only if those raw strings occur in the stored records; this inventory contains their normalized names instead. The report retains each original input. For the 26 NOAA station IDs researched in [c5y-n8r #148](https://github.com/openwatersio/c5y-n8r/issues/148), the exact stored `Virgin Islands` spelling is interpreted as `United States Virgin Islands` before lookup. This requires the NOAA source name and a listed station ID; missing, different or unresearched context leaves the bare input unresolved. The NOAA importer obtains these stored names from the geocoder, which translates each place’s ISO code through `country-code-lookup`; `Virgin Islands` is that library’s VI display name. The maritime-zone and curated-location paths in `resolveMetadata` also hold ISO codes before choosing a display name. Production should preserve those identities rather than adopt this hand-maintained diagnostic station list. A new NOAA station or changed place result requires fresh context review; it is not automatically added to the mapping. The [mapping evidence](../spikes/country-resolver/noaa-virgin-islands.json) records per-station benchmark and MDAPI URLs, hashes recorded at retrieval, source passages and retrieval times. The repository retains excerpts rather than the full responses; the hashes can be compared with a subsequent download but cannot authenticate the excerpts without the original response bytes. NOAA benchmark location descriptions establish the territorial context; MDAPI state alone is inconsistent. Coral Harbor (9751373) has no benchmark state abbreviation; its retained sheet passage identifies Western St John and Cruz Bay, and its API state is VI. The other 25 sheets explicitly give VI. This consumer interpretation adds no worldwide library alias. Production callers currently pass only a country string, so a resolver switch must first carry source context through normalization or retain the original ISO identity; the contextual coverage table is not a drop-in production result. NOAA jurisdiction filtering is also keyed by country name and must retain its authority behavior when names change. Reports retain `input`, `lookupInput` and every applied `sourceMappings` entry alongside the library provenance. Existing answers are migration baselines; disagreements require tracing provenance and deciding compatibility behavior.

Root installs and release jobs do not install or execute the spike dependency. Its tests and typecheck run only through the explicit spike check command above; CI does not run them. This keeps the production lockfile policy intact.

A normal Git install builds the compiled reader through its prepare step. A fresh Git install with scripts disabled does not contain the compiled reader. Prepared package tarballs contain that reader and support script-disabled installation; they are checked separately in [code PR 273](https://github.com/openwatersio/c5y-n8r/pull/273). The standalone lockfile pins its runtime dependencies. The explicit Git install remains outside the production registry-only lockfile gate. The package is private and unpublished on npm.

For 38 comparison groups, the production `Americas` vocabulary becomes `North America` or `South America`; Russia changes from Asia to Europe and British Indian Ocean Territory from Asia to Africa. Published filters such as `station.continent === "Americas"` would need an explicit compatibility decision. These vocabulary and classification differences extend beyond the Curaçao case linked below.

## Adapter limits

The Node adapter loads the binary and injects the registry into the browser-safe `lookup.ts` helper. The contextual station evidence is imported only by the Node report, separately from that helper. The helper calls the library’s `convert` API directly; it does not enumerate possible codes or maintain a separate country table. Missing, ambiguous, retired and deprecated sources or targets remain unresolved. Tentative undated source and target assignments remain usable, with their temporal uncertainty and upstream provenance retained in the report. Missing temporal bounds are not replaced with invented dates.

The `countryByIso` helper compares alphabetic alpha-2 and alpha-3 codes; numeric ISO callers remain outside this comparison. The diagnostic projects results into the existing caller fields. The report additionally retains selection, uncertainty, evidence status and candidate evidence. The projection is diagnostic; production activation still requires the integration and compatibility work described here. The pinned dataset retains its existing certification-status labels, independently of whether a faithful upstream fact is admissible. The summary counts tentative resolutions separately, and the corpus is selected around these Slackwater inputs; these figures do not measure general name coverage.

Timings include package loading and validated binary opening. A local run took about 22 ms to open/import and 113 ms for 8,728 conversion lookups after contextual interpretation. That lookup loop excludes source-context mapping time. These are single-machine measurements, not comparative performance claims.

The production builder is exported to Node, browser and worker consumers. Adopting a static Node filesystem loader there would break browser/worker use. Consumers must supply bytes appropriately before adoption; the library reader already accepts bytes.
