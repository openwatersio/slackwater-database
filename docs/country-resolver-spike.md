# Historical country resolver comparison

This standalone diagnostic preserves the comparison that informed the [released country resolver](country-resolver.md). It evaluates the earlier c5y-n8r dataset 5 at commit `ea6fe2e59e2e829242fd3640eb58b23913624cb7` against the frozen `country-code-lookup` 0.2.1 baseline. The published database uses dataset 6. The comparison reports unresolved inputs and leaves station data untouched.

Faithful ingestion of Wikidata labels, aliases and claims is trusted for data admission, with source revisions, statement identities and qualifiers preserved in provenance. Independent certification and complete upstream references are optional quality signals, pursued asynchronously. They do not block admission of faithfully mapped upstream facts. Local aliases, territory interpretations and other project policy decisions still need explicit provenance and compatibility decisions.

## Run

Use the repository’s pinned Node/npm versions and run `npm ci`. Install the diagnostic separately, then run it:

```sh
npm ci
npm ci --prefix spikes/country-resolver
npm run check --prefix spikes/country-resolver
npm run report:country-resolver -w packages/stations
```

The command writes `tmp/country-resolver.json`. An optional argument sets another output path, relative to the command’s working directory (`packages/stations` for the workspace command). Country values must be nonempty strings within the reader’s 1,024-character limit; invalid records stop the diagnostic. The report reads every source JSON record in `data/` and compares its country input with `countryByName`, using the frozen baseline name-lookup function. Its Western Samoa and Cape Verde aliases apply only if those raw strings occur in the stored records; this inventory contains their normalized names instead. The report retains each original input. For the 26 NOAA station IDs researched in [c5y-n8r #148](https://github.com/openwatersio/c5y-n8r/issues/148), the exact stored `Virgin Islands` spelling is interpreted as `United States Virgin Islands` before lookup. This requires the NOAA source name and a listed station ID; missing, different or unresearched context leaves the bare input unresolved. The frozen comparison inventory’s NOAA names came from the former geocoder’s `country-code-lookup` projection; `Virgin Islands` is that package’s VI display name. Production geocoding uses c5y-n8r and preserves the ISO identity. The maritime-zone and curated-location paths in `resolveMetadata` also hold ISO codes before choosing a display name. Production should preserve those identities rather than adopt this hand-maintained diagnostic station list. A new NOAA station or changed place result requires fresh context review; it is not automatically added to the mapping. The [mapping evidence](../spikes/country-resolver/noaa-virgin-islands.json) records per-station benchmark and MDAPI URLs, hashes recorded at retrieval, source passages and retrieval times. The repository retains excerpts rather than the full responses; the hashes can be compared with a subsequent download but cannot authenticate the excerpts without the original response bytes. NOAA benchmark location descriptions establish the territorial context; MDAPI state alone is inconsistent. Coral Harbor (9751373) has no benchmark state abbreviation; its retained sheet passage identifies Western St John and Cruz Bay, and its API state is VI. The other 25 sheets explicitly give VI. This consumer interpretation adds no worldwide library alias. Production source records now retain their original ISO identity in `country_code`; the contextual coverage table is not a drop-in production result. NOAA jurisdiction filtering now uses ISO alpha-2 codes, preserving authority across display-name changes. Reports retain `input`, `lookupInput`, `lookupNamespace` and every applied `sourceMappings` entry alongside the library provenance. Existing answers are migration baselines; disagreements require tracing provenance and deciding compatibility behavior.

Root installs and release jobs do not install or execute the spike dependency. Its tests and typecheck run only through the explicit spike check command above; CI does not run them. This keeps the production lockfile checks, including the exact immutable country dependency exception.

A normal Git install builds the compiled reader through its prepare step. A fresh Git install with scripts disabled does not contain the compiled reader. Prepared package tarballs contain that reader and support script-disabled installation; they are checked separately in [code PR 273](https://github.com/openwatersio/c5y-n8r/pull/273). The standalone lockfile pins its runtime dependencies. The standalone diagnostic Git install has its own lockfile. The production root-lockfile gate allows its separately declared immutable c5y-n8r commit alongside npm registry packages. CI also fetches that commit’s build lockfile and validates its prepare dependencies as integrity-pinned npm registry packages. The package is private and unpublished on npm.

The report preserves both the source match and target-code candidates, including applicability, tentative status and evidence. The report hashes the same bytes opened by the adapter and records their SHA-256 alongside the metadata. It groups comparisons by original input, interpreted value and namespace, so an unresearched record with the same country spelling remains a separate unresolved group. `inputs` counts distinct raw inputs; `comparisonGroups` counts those context-specific groups. `resolvedInputs` counts only raw inputs whose groups all resolve. Fields ending in `Groups` count comparison groups. Outcome `groups` counts may exceed the raw input total when contexts differ.

The Netherlands candidate uses the Kingdom entity Q29999, which has an exact English alias and the NL assignment. The inventory excludes additional inputs in CHS, currents, curated locations, place metadata and maritime zones. Full source-record coverage alone does not establish migration readiness. ISO-code callers in geocoding, normalization, name cleanup, maritime-zone conversion and the published builder’s exact code/name consistency check also need coverage. The diagnostic's `identityAudit` compares every stored code with the candidate's contextual lookup of its source label and also checks that the candidate recognizes the code; all 8,728 records currently match, with no missing, invalid, unresolved or changed codes. Of the 48 comparison groups with metadata differences, nine change names and 41 change continents. Saint Helena changes the old library’s Atlantic Ocean display category to the territory’s upstream Africa continent; Myanmar uses the imported Myanmar display label. For 38 comparison groups, the production `Americas` vocabulary becomes `North America` or `South America`; Russia changes from Asia to Europe and British Indian Ocean Territory from Asia to Africa. Published filters such as `station.continent === "Americas"` would need an explicit compatibility decision. ## Adapter limits

The Node adapter loads the binary and injects the registry into the browser-safe `lookup.ts` helper. The contextual station evidence is imported only by the Node report, separately from that helper. The helper calls the library’s `convert` API directly; it does not enumerate possible codes or maintain a separate country table. Missing, ambiguous, retired and deprecated sources or targets remain unresolved. Tentative undated source and target assignments remain usable, with their temporal uncertainty and upstream provenance retained in the report. Missing temporal bounds are not replaced with invented dates.

The `countryByIso` helper compares alphabetic alpha-2 and alpha-3 codes; numeric ISO callers remain outside this comparison. The diagnostic projects results into the existing caller fields. The report additionally retains selection, uncertainty, evidence status and candidate evidence. The projection is diagnostic; production compatibility is covered separately in [Country resolution](country-resolver.md). The pinned dataset retains its existing certification-status labels, independently of whether a faithful upstream fact is admissible. The summary counts tentative resolutions separately, and the corpus is selected around these Slackwater inputs; these figures do not measure general name coverage.

Timings include package loading and validated binary opening. A local dataset-5 run took about 18 ms to open/import and 111 ms for 8,728 conversion lookups after contextual interpretation. That lookup loop excludes source-context mapping time. These are single-machine measurements, not comparative performance claims.

The production builder is exported to Node, browser and worker consumers. Adopting a static Node filesystem loader there would break browser/worker use. The shipped database embeds the bytes for each target. See [Country resolution](country-resolver.md).

## TICON Saint Helena scope

The [TICON extract](../spikes/country-resolver/ticon-saint-helena.json) records the original `country=SHN` for exactly three stored series (50 constituent rows each), including the full CSV URL and recorded hash. Their identifiers are matched with source name TICON-4 and the stored Saint Helena spelling. The report looks up SHN in the ISO alpha-3 namespace, selecting the territory Q192184 rather than assigning a country code to island Q34497. Missing or different provider context remains unresolved. The separate NOC series supplies GBR and keeps its existing United Kingdom identity; it cannot inherit the SHN mapping.

The ISO-bearing territory is admitted by [c5y-n8r #280](https://github.com/openwatersio/c5y-n8r/pull/280). The dependency pins that PR's exact public commit; a merge is not implied by the pin. Its dataset 5 also includes the Myanmar compatibility alias from merged #278. The bare library name Saint Helena remains the island with no country-code target. Unknown assignment dates remain unknown; the diagnostic uses undated current-code selection, not a claim about which official territory name or code applied during a record's measurement epoch. Missing territory references are tracked asynchronously in [#279](https://github.com/openwatersio/c5y-n8r/issues/279).

The production TICON importer now preserves the ISO identity from the original CSV alpha-3 value. The three-record extract retains the evidence for interpreting the cached display label during the earlier comparison.

The consumer extract is modified TICON-4 data under CC BY 4.0 for these three records, with Hart-Davis, Dettmering and Seitz (2025) attribution, DOI and source license links preserved in the file. The separate Wikidata runtime country dataset remains CC0. Full CSV bytes are not redistributed in the spike; the recorded hash does not authenticate a partial excerpt without the original response.
